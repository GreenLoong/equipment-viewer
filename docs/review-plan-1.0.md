# 0.3—1.0 独立审查与质量验证计划

日期：2026-10-08。状态：跨版本审查计划，尚未对新增实现作通过结论。

## 1. 审查边界与证据

主管通知某版本实现和集成验证完成后，审查者读取有效 AGENTS、工程规范、该版本功能卡、实际 Git 差异、新文件、必要调用上下文和验证记录。记录基线/提交/关键文件哈希。当前阶段不把未集成代码当最终缺陷，也不以测试通过替代源码判断。

实现者运行、审查者独立静态检查、审查者自行运行、模拟用户验收与真实用户体验分别记录。用户已授权连续 Agent 开发，不恢复逐功能等待用户确认的旧流程；下载、GitHub 同步由主管执行。本计划不是零漏洞或零内存泄露保证。

缺陷报告包含文件与行、触发输入/操作、预期与实际、影响、必要修正和复验范围。内存安全、资料丢失、错误权限或不受控资源增长为阻断项；纯格式偏好列建议。行为或接口修复后重新审查关联调用与失败路径。最终包需对应已经检查的实现，文档或截图不能证明二进制一致。

## 2. 每版共同检查

- 确认文件负责人、现有用户改动、当前分支和差异；不清库、不 reset/clean，不把忽略的数据备份交给 Git。
- 脚本首次/改变后先读内容与被调用对象，再运行；自动检查使用临时数据库、受控服务器和临时端口，不写正常资料。
- 必填字段、字段类型、ID、大小、数量、有限数值、未知值、编码和错误恢复均有实际依据；输入失败不破坏旧输出和当前显示。
- 属性、清单、三维、过滤、选中、显隐和隔离由明确状态源协调。失败保留完整状态，成功切换重置规定状态。
- 业务失败不能伪装成功或正常空集合；提交成功后的读取失败准确说明已保存，避免用户重试造成重复。
- 注释说明所有权、借用失效、事务与信号阻塞等非显然约束；公开接口符合当前 Doxygen 规范。
- 回归既有记录、导入持久化、设备切换、同名零件、形状字段清理、显隐/搜索与三维交互。复杂度/数量限制明确，不以少量样例声称性能达标。

## 3. 内存、资源与生命周期专项

### 3.1 所有权静态审查

- 列出资源创建→拥有者→正常释放→失败释放路径：QObject、非 QObject、SQL 连接/查询、文件、线程、网络回复、计时器、GPU 程序/缓冲、服务端游标/连接池。
- QObject 依父子所有权释放；智能指针与 Qt 父对象不可形成重复释放。动态控件重建、替换和 deleteLater 必须核对事件循环及销毁顺序。
- Part、容器元素、窗口、控制器和 Repository 借用不能跨重新加载、容器 detach/替换、异步任务或拥有者销毁保留。异步任务使用值快照、有效性守卫或明确寿命契约。
- lambda 捕获 this、引用和局部变量逐个核对；接收上下文只能保护其自身生命周期，不能自动保证其他被捕获对象有效。取消/销毁后不得访问已销毁状态。
- 重复加载不能累积 connect、事件过滤器、线程、计时器或历史数据；线程终止等待有界，UI 不忙等也不使用强制终止掩盖问题。
- OpenGL 清理在有效上下文进行，取消上下文销毁回调后才析构派生成员；重建上下文、父窗关闭、回退替换、失败初始化分别覆盖。持有 SceneData 的子控件应先于数据销毁。

### 3.2 有效资源测试

- 先预热再反复创建/加载/切换/销毁；统计 QObject、未完成网络回复、活动计时器/线程、SQL 具名连接数、文件/句柄（可获得时），不只看程序是否退出。
- 至少测：100 次设备加载/选择清除/显隐恢复；20 次窗口创建关闭；20 次非法导入后合法导入；网络阶段各 100 次成功/失败/超时/取消请求。计数回到基线或稳定有解释的缓存上限。
- 重复窗口测试包含实际父窗拥有三维控件的销毁，原生 GL 与软件回退分别记录；在有请求或计时器未完成时关闭窗口。
- RSS/Private Bytes 是趋势辅证，不能直接等同泄露；GPU/驱动和分配器保留可能波动。记录预热、迭代次数、采样条件，持续单调增长则追踪实际资源来源。
- 可用内存检测器实际运行后才声明覆盖；检查越界、use-after-free、重复释放和泄露的适用范围。系统/框架噪声只在能说明来源时排除，不吞掉应用错误。

## 5. 网络专项细则（0.4起）

- QNetworkAccessManager 有明确长寿命拥有者；每个 QNetworkReply 成功/HTTP错误/传输错误/超时/取消都恰当释放。deleteLater 后处理事件再断言资源释放，不以原始指针继续读。
- 每个请求有有限总时限；传输超时与总时限区别明确。超时 abort 后的 finished/error 回调不会重复提交状态、弹重复错误或访问销毁对象。
- request ID/世代号及设备ID防止旧回复覆盖新状态；新请求、设备切换、窗口销毁和服务端重连都核对失效策略。
- 响应大小与解析数量有限，流式累计在超过限额时停止；不要只在 readAll 之后检查已经分配的巨量内容。错误和畸形内容保留旧视图。
- UI线程不执行阻塞数据库/网络等待，不通过 processEvents 的重入循环模拟异步。信号处理顺序和多次回调有测试。
- 受控测试服务监听本机临时端口、自动清理，不外发消息；记录认证/开放范围的实际约定。MySQL凭证留服务端配置，不进入Qt包或Git。
- 重试有次数、间隔和总预算；非幂等保存不得盲目重试，先明确操作ID/冲突或状态查询策略。

## 6. SQL、批注与缓存专项细则

- 数据参数绑定；每条执行、事务、提交和回滚结果检查；失败不能清空正常资料。唯一/外键/尺寸/文本规则同时在输入与数据库落实。
- MySQL连接池和游标在成功、异常、超时及请求取消路径释放；每请求事务边界明确，失败回滚后再归还连接。测试锁等待/连接中断要有时限。
- 迁移前一致性备份并验证；升级失败保留旧库，可恢复且不自动删除。恢复仅在独立路径演练，不覆盖正常资料。
- 批注接口须明确新增/更新的权限、长度、并发版本与重复请求行为；设备/零件ID和查询条件一致，文本显示遵守纯文本约定。
- 缓存key包含影响结果的ID/权限范围/数据版本等必要维度，不跨设备或用户串值。错误值不进入正常数据流，缓存失败不会阻止合法数据库读取。
- 失效与写入之间的竞态明确；不能只用“删除一次key”证明不会读旧资料。测试回源发生在写入前而填缓存发生在写入后的顺序。缓存锁/后台任务有上限和退出路径。
