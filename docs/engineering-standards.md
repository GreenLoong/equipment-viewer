# 设备模型查看器技术规范 v1.0

生效日期：2026-10-08。适用范围：D:/作业/简历/工作模拟，当前桌面交付及后续模拟需求迭代。

工程内 docs/engineering-standards.md 为执行依据；本文件是本次交付快照。规范调整需同步快照与工程文档，不将未执行的检查写为通过。

## 1. 交付目标与协作规则

用户已授权全部由 Agent 开发并连续推进到可交互桌面交付，取消用户必须编写关键逻辑及每个小功能前等待人工验收的旧约定。保留已经发生的真实验收记录；自动检查、模拟验收及真实人工验收分别记录。

所有工作按“功能卡 → 实现 → 运行验证 → 独立审查 → 修复及复验 → 文档 → 集成交付”推进。真实用户反馈与模拟用户反馈必须注明来源。默认只新增有业务用途、能观察结果的小功能；模拟反馈不无限生成任务。

本次桌面完成条件：设备选择与持久化、JSON 导入、零件清单及只读属性、三维模型、旋转缩放与查看全部、选择高亮、隐藏与恢复，以及两项模拟反馈驱动的搜索和隔离查看。网络、MySQL、Redis 作为后续有独立验收范围的扩展，不是本轮本地运行依赖。

不删除或覆盖已有正常数据；不重置用户工作区。原记录功能继续可用。远程推送、发布和新增费用仍按已有具体授权处理，本轮不扩大这些授权。

## 2. 工具链与目录

- C++17；Qt 6.11.1 MinGW 64 位；匹配的 MinGW GCC 13.1.0；CMake + Ninja；QSQLITE。
- 三维优先使用本机 Qt OpenGL/OpenGLWidgets；无图形上下文的自动测试有明确软件投影回退，不能将回退测试声称为原生 OpenGL 验证。
- src/：数据对象、Repository、Controller、Importer、窗口及三维组件。
- tests/：临时数据驱动的功能与异常检查。
- samples/：可导入的虚构 JSON，明确示例用途；不放真实客户资料。
- scripts/：已检查的构建、运行及交付入口。
- docs/：工程规范与当前交付/模拟反馈记录；README 保留实际运行入口，验证记录维护真实结果。
- build/、运行数据库、本地配置及凭证忽略，不进入 Git。
- 不为尚未确定的服务建立空目录或通用框架，不引入当前功能不需要的依赖。

## 3. 命名、格式与接口

- 类型使用 PascalCase；函数和变量使用 lowerCamelCase；私有数据成员沿用 member_ 后缀；头文件使用 #pragma once；文件名沿用小写类名风格。
- 缩进四个空格，沿用现有花括号换行风格。头文件直接包含其需要的类型，避免依赖间接包含；禁止 using namespace std。
- 同类接口参数表达用途，传大型只读 Qt 对象用 const 引用；查询结果不得暴露可变内部容器。
- Qt 父子关系管理控件，其他资源使用 RAII。借用指针明确生命周期，禁止保存重新加载后失效的 Part 指针；不使用裸 new 管理无父对象的长期资源。
- 预期业务失败沿用 bool 返回与可读 QString 错误，不以未捕获异常作为正常流程。错误至少说明操作和可定位对象；输入校验错误指出字段或零件。
- IDs 按原文精确比较，设备 ID 与设备内零件 ID 共同定位跨设备对象。名称不做身份标识，允许重复。

## 4. 模块边界与状态

- EquipmentRepository：数据库连接、结构检查、事务保存和查询；不操作控件、网络或文件对话框。
- EquipmentImporter：将 JSON 转成完整 Equipment/Part 数据；失败不改调用者的原输出；不写数据库。
- EquipmentController：当前设备、零件、选中 ID、可见性及隔离状态的唯一业务来源；只在完整加载成功后替换状态。
- EquipmentWindow：设备选择、清单、属性、导入、过滤及状态提示；不写 SQL；根据 ID 请求控制器操作。
- SceneView：接收当前零件、选中 ID、隐藏集合并绘制；将用户选择回传为 ID；不访问数据库。
- 模块间传入数据对象或明确参数，不把控件指针传给 Repository 或 Controller。
- 开始并行前固定公共接口；调整接口由主管协调并通知调用方。构建、入口与公共文档由主管统一维护。

## 5. 注释要求

- 新增公开类和公开业务接口使用简短中文 Doxygen 注释（/** ... */），说明职责、输入输出、失败行为；涉及借用指针时说明失效条件。
- 非显然约束必须注释原因：事务范围、信号阻塞、无效选择恢复、形状字段清空、OpenGL/软件回退、坐标轴或相机约定。
- 注释解释原因与约束，不逐行翻译代码。简单赋值、循环不堆注释。
- 测试涉及模拟失败时说明制造方式和预期保护的行为。
- 不留没有任务编号与后续处理说明的 TODO/FIXME；本轮未实现内容写入交付记录，不写空壳完成声明。

## 6. 数据与业务规则

- JSON：equipmentId、equipmentName、parts；零件包含 id、name、material、shape、dimensions、position。
- 必填文本拒绝空白；字段类型检查严格；未知 shape 拒绝；box 的 dimensions 为三项，cylinder 为半径、长度两项，position 为三项。
- 坐标和尺寸均为有限数值，尺寸为正；单位毫米，Z 向上，几何体中心为 position，圆柱轴线沿 X。
- 窗口读入 JSON 文件上限 5 MiB，解析上限 10000 个零件；超过限制明确提示。加载三维时对极端数值做安全归一化或显示可解释的范围错误，不让无效浮点值进入渲染。
- 完整校验后再以现有事务保存设备及全部零件；已有设备 ID 拒绝覆盖。SQL 值必须参数绑定；连接显式启用并检查外键。
- 数据库异常与空设备区分；读取或导入失败保留当前设备和正常资料；错误不中断后续合法操作。
- 参数第一版只读；shape 对应的不适用字段清空并隐藏，中文文本按纯文本显示。
- 隐藏零件保持当前选择和属性，选择隐藏零件不自动显示；显示全部清除隔离并恢复全部零件，保留选择；无选择时隐藏与隔离按钮不可用。
- 设备切换成功后清空选择、显隐和隔离状态；搜索只过滤清单，不修改模型可见性。过滤隐藏选中行时清空选择，模型显隐状态保留。

## 7. 三维与交互

- 建立以数据单位为依据的 box/cylinder 几何体，尺寸方向与数据约定一致；不引入真实 CAD 解析。
- 左键短点击拾取零件，左键拖动旋转，滚轮缩放，按钮恢复查看全部；按 ID 与清单联动。
- 选中使用可辨识高亮，隐藏对象不可拾取。相机与视口 resize 正确更新；空场景给出提示。
- 渲染资源按上下文生命周期释放；优先清晰实现，不引入未测性能优化。鼠标点击与拖动使用明确阈值，避免拖动后误选。
- 模型复杂度及渲染性能限制如实记录。若最终 OpenGL 验证失败但软件回退可用，交付说明必须披露。

## 8. 验证与独立审查

- 首次运行新增或修改的安装、构建、测试和迁移脚本前，检查脚本及调用对象。默认不下载依赖。
- 验证至少包含受影响模块构建、重要业务路径、失败保护与旧功能回归。测试使用临时文件或明确的受控数据，不操作正常数据库。
- 有效测试：类型/字段错误、重复 ID、不留下半份资料、失败保留当前状态、同名零件、形状切换、显隐与搜索边界、重启持久化。不要以断言控件存在替代行为验证。
- 原生三维运行需要实际窗口和截图验证；offscreen 的数据/交互测试不替代原生渲染检查。
- 独立审查者读取实际差异、需求和验证依据，只读实现文件。意见包含位置、触发条件、影响、修改理由；纯偏好标建议。
- 阻断问题修复后复验；行为或接口改变必须独立复查关联路径。结果对应明确差异、提交或文件哈希。
- 本轮交付报告准确区分构建、运行、自动检查、独立审查、模拟验收和真实人工验收。

## 9. 技术文档与交付

- README：本机与打包后的实际启动方式、必要输入、支持操作、已知限制和排错；变更入口即更新说明。
- 验证记录：实际命令、环境、结果、审查范围及尚未验证事项。不能提前写“通过”。
- 模拟反馈台账：编号、模拟用户角色、情境与反馈、需求决定、验收条件、实施结果。明确写“模拟”，不冒充真实反馈。
- 技术规范维护：重大规则变化记录日期、原因和影响，各 Agent 实施前读取有效版本。
- 用户交付：可运行桌面包、启动入口、至少两份虚构可导入样例、简短操作指南与验证/限制说明；最终交互验收由用户实际体验。

## 11. 中断检查点与恢复

- AGENTS.md 必须直接指向 docs/working-state.md、有效规范、构建入口和当前任务；旧会话不是唯一状态来源。
- 主管维护 working-state：当前完成目标、授权边界、基线提交、文件负责人、完成/进行中/阻塞任务、实际验证、下一步及已知风险。
- 每个 Agent 保存自己的 docs/handoffs/<角色>.md。里程碑完成、接口变更、出现阻塞、结束工作前更新；包含已落盘文件、未完成部分、实际检查和接手入口。
- 文件编辑及时落盘；完成一个可运行阶段且检查通过后建立本地 Git 检查点。尚未完成阶段保持工作区，记录文件与下一步，不误记为通过或丢弃改动。
- 源码与正常数据库分别保护：源码依赖本地提交与已保存文件；数据库采用一致性备份，不在有写入者时仅复制裸数据库文件。备份必须验证可读性；无一致性工具时先保留原库并说明备份尚未完成，不声称安全快照。
- 额度或执行中断发生时，不保证能及时再写最后一份记录；使用最近的已落盘检查点恢复。不要承诺额度刷新后自动启动子 Agent，用户可重新发送恢复指令。
- 恢复先读取 AGENTS、working-state、角色交接；检查实际 Git 状态、差异和工具进程，再按最小受影响范围验证。若原 Agent 仍工作，先协调负责人；已不存在则重新分配，不假设旧 Agent ID 或内存仍有效。
- 不能为恢复而执行 reset --hard、clean、删除数据库或清理未完成文件；失效的检查结论需要更新。外部发布与新增费用仍需核对授权。
