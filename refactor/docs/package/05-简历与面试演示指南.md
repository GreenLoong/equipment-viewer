# 简历、面试与演示指南（设备模型查看器 1.2.0）

读者：把这个项目写进简历、或要在面试/现场演示里讲清楚它的人。
原则：只讲仓库里能当场验证的东西；版本、测试数、性能结论都给出出处，不夸大。

## 1. 先用一句话定位

“Windows 桌面端工业设备与机械 CAD 三维查看器：C++17 + Qt6 Widgets + OpenGL + SQLite，
自研二进制网格格式与严格校验，STEP 转换在受限子进程内完成，打包成双击即用的单机程序。”

不要在定位里写“平台”“系统”“框架”：它是一个**客户端工具**，规模是个人项目量级（约 1.1 万行，
实现 5.2 千行 / 测试 5.4 千行，49 个源文件）。

## 2. 简历怎么写

精简版（占 3–4 行，适合一页简历）：

> **工业设备 / CAD 三维查看器**（个人项目 · C++17 / Qt6 / OpenGL / SQLite）
> - 独立完成架构、实现、测试与打包：设备参数与 STEP 装配导入、本地持久化、三维交互查看，
>   一键打包成自带运行库、双击即用的 Windows 程序。
> - 自研 EVM1 二进制网格格式（计数 + SHA256 + 拓扑自洽校验），STEP 转换由私有 Python/OCP
>   运行库在受限子进程内完成，超时/取消/失败都不破坏原有资料。
> - 渲染侧用自建 FBO 实测 4×MSAA + 2×超采样，曲面按顶点法线平滑着色（实测 FBO samples=4，
>   渲染描述如实上报当前路径，不按请求值宣称）。
> - 17 项 CTest 全通过，另有原生窗口 harness 做像素级抗锯齿与交互契约验收、资源基线复验；
>   重构时用克隆检测脚本消除 18 类重复实现。

详细版（项目经历里多写 2–3 行）：

> - **架构与约束**：`EquipmentWindow → Controller → Repository/Importer → SceneView` 单向数据流；
>   Controller 是设备/选中/隐藏/隔离状态的唯一来源，Window 不执行 SQL，场景不访问数据库，
>   导入失败不改变调用方已有状态（避免“半份数据”）。
> - **稳定性**：SQLite 结构校验 + 参数绑定事务 + 回滚；转换进程 Job 约束与看门狗；
>   交付包只含运行文件（不含数据库与凭证），并用清单记录版本、提交、文件数与 exe 哈希。
> - **工程方法**：自动检查（CTest）、原生图形验收、独立审查、模拟用户验收与真人验收分开记录，
>   不互相替代；已知的间歇性用例与未覆盖场景如实写进验证记录。

写简历时把数字写准（都以当前仓库为准）：17 项 CTest、真实 STEP 样例 6 件装配 4162 顶点 /
4332 三角、历史版本验证过 82 件装配 157558 顶点 / 175598 三角、重构消除 18 类重复实现。

## 3. 面试讲解顺序

**30 秒版**：这个程序解决“把机械 CAD 装配和参数化设备拿到非 CAD 环境里查看”的问题——
导入 JSON 或 STEP，保存在本地 SQLite，用 Qt 做界面、OpenGL 做三维查看，最后打包成一个
双击就能跑、不需要装 Qt/Python/CAD 的文件夹。我独立做完了从架构、实现到测试、打包的全流程。

**3 分钟版**（按这条主线讲，别按文件讲）：

1. **数据入口**：两套导入。JSON 是参数化设备（`box`/`cylinder` + 尺寸 + 位置），做严格字段校验；
   STEP 交给随包的私有 Python/OCP 运行库在**独立子进程**里做三角化，程序侧只接收协议 JSON，
   再用 EVM1 二进制装网格。为什么要隔进程：CAD 内核崩溃、卡死、内存暴涨都不能带崩界面，
   所以有超时、取消、退出确认和 PID 断言。
2. **数据落地**：SQLite 单文件库，启动时校验表结构（列数、非空、版本），不匹配就拒绝启动而不是
   清库；写入走参数绑定事务，失败回滚；重复设备 ID、重复 CAD 内容都拒绝覆盖。
3. **查看与交互**：Controller 持有唯一状态，Window 只做展示和转发，SceneView 负责几何与绘制；
   拾取、隐藏、隔离、搜索、四种视图、有序展开、单件拉远都是内存态，显示偏移是毫米副本，
   不回写库——所以“演示过的位移”不会污染源数据。
4. **渲染**：有原生上下文走 OpenGL（VBO + 深度缓冲），没有就走画家排序的软件回退，并且把当前
   实际路径写进渲染描述，测试据此断言；抗锯齿是自建 FBO 请求 4×MSAA 再做 2×超采样，
   实测采样数从本次 FBO 读，而不是把请求值当结果。
5. **工程质量**：CTest 全量 + 原生窗口 harness（像素级） + 资源基线 + 真实 STEP 端到端 +
   打包后包内冒烟；重构阶段写克隆检测脚本量化重复度，并用哈希清单保证“重构版的测试没有被改弱”。

**15 分钟版**：在 3 分钟版之上，打开 `文档\03-验证记录.md` 讲验证证据，打开
`文档\04-重复实现审查与去重报告.md` 讲重构方法与残留项，最后现场演示（见第 7 节）。

## 4. 高频追问与回答要点

| 追问 | 回答要点 |
| --- | --- |
| 为什么不用现成的 CAD 控件（如 OCCT 的 viewer）？ | 本项目要练的是“自己做三维管线”：几何生成、相机、拾取、绘制、回退路径都要可控可测。OCCT 只在转换进程里用来读 STEP 实体，界面不依赖它。 |
| 为什么不直接显示 STEP 原始拓扑？ | 查看器只需要可视化，三角网格 + 外包络足够；保留原始实体反而把 CAD 内核耦合进界面。代价是丢掉了 B-Rep 语义（制造标注因此做不了）。 |
| 网格数据为什么要自定义二进制格式？ | JSON base64 体积大、解析慢且难做完整性校验。EVM1 是定长头 + 计数 + SHA256 + 浮点数组，读入时校验长度/计数/拓扑（退化三角、索引越界、NaN），不合法整份拒绝。 |
| 怎么保证转换进程不出问题？ | 独立进程 + Windows Job 约束（子进程一起回收）、看门狗超时、取消、退出确认；测试断言取消后 `processId()==0`，失败/取消后原设备与指纹不变。 |
| 数据库结构改了怎么办？ | 启动做结构校验与迁移：列数/非空/版本号逐项比对，能迁移就迁移，不能就明确拒绝并给出原因；不做“清库重建”。 |
| 抗锯齿是怎么做的？ | 三维绘制进自建帧缓冲，请求 4×MSAA，再以“每逻辑像素至少 2×2 渲染像素”超采样解析回控件；实际采样数由本次 FBO 读出写进渲染描述。软件回退路径不宣称 MSAA。 |
| 曲面“锯齿感”的真正原因？ | 不是采样不足，而是逐面片平光（每个三角面一个法线，相邻面之间出现亮度台阶）。改成顶点法线平滑着色：平面体保持硬边、圆柱用解析径向法线、STEP 网格按共享顶点累加相邻面法线（>50° 仍按硬边），光照用半球环境光 + 单向漫反射。 |
| 右下角坐标轴怎么做？ | 方向取世界轴在相机空间的真实投影（不归一化，轴接近视线方向时自然压短）；右下角按网页版同一管线：先在 120 像素画布上光栅化，再平滑缩放到 105 像素显示。三视图每栏用自己的视线，不共用首栏朝向。 |
| 你怎么知道界面没泄漏？ | 有独立资源 harness：反复创建销毁窗口/场景，统计控件、窗口、QObject 子树与 SQL 连接数，必须回到基线；只说“自有对象全部回收”，不说“零泄漏”。 |
| 测试里为什么会有 offscreen 和原生两种跑法？ | offscreen 是软件回退路径，能覆盖逻辑回归但不能替代真实 OpenGL；原生 `-platform windows` 跑 FBO 采样数、像素过渡、鼠标契约这些必须真窗口的断言。 |
| 重构怎么证明没改行为？ | 公开签名、对象名、用户可见文案保持一致；`refactor/tests` 与原 `tests` 用哈希清单比对（有意分叉的 3 个文件单独标注）；重复度用克隆检测脚本量化（≥60 词重复组 60→50，`sceneview.cpp` 的 ≥80 词重复 7 组→0）；全量 CTest 与原生 harness 复跑。 |
| 最大的坑是什么？ | 两条：一是曾用 PowerShell 脚本做整文件替换，编码转换把中文注释写坏，改成补丁编辑 + 复核，并把这个教训写进协作约定；二是“看起来的显示问题”往往不是表面原因——锯齿的真因是平光，坐标轴的真因是把方向向量归一化并固定像素长度。 |
| 有没有没做完的？ | 有，见第 6 节，我会直接说没做的部分，不把“能跑”说成“完工”。 |

## 5. 可以讲的真实难点（按“现象—定位—解决—证据”讲）

1. **中文路径下的构建**：CMake/Ninja 在含中文的绝对路径下生成目标文件失败。解决：构建脚本用
   相对 `-S/-B` 写法并固定工具链参数，把“部署 Qt 运行库”“同步 CAD 运行库”“打包”串成一条命令。
   证据：`refactor/build.ps1` 一条命令完成配置、构建、部署、同步与 17 项 CTest。
2. **CAD 转换进程的失败面**：转换器可能崩溃、卡死、超时、被用户取消、退出码不可信。解决：
   子进程 + Job 约束 + 看门狗 + 退出确认，协议报文严格校验（协议名、字段、计数、SHA256），
   任何一种失败都保持原设备、原指纹不变。证据：`cad_import_process` 用例与真实 STEP 端到端。
3. **“锯齿”根因不是采样**：先提高了采样仍然有台阶感，定位到逐面片平光；改为顶点法线平滑着色，
   并让实测采样数进入渲染描述与断言，而不是写死请求值。
4. **方向轴与网页版不一致**：把方向向量归一化 + 固定像素长度，导致轴永不“压短”、
   X/Y 轴出现 180°/0° 的镜像。改为相机空间真实投影，并复刻网页版“120 像素画布 → 105 像素显示”
   的非整数缩放管线，把细线台阶摊成亚像素过渡。
5. **状态泄漏**：三视图里整栏被实体色填充，根因是坐标轴绘制改过画刷后没有恢复；修复方式是
   每栏绘制前显式复位状态，并加像素断言防止回归。
6. **重构不能改行为**：写克隆检测脚本量化重复度，抽 4 个内部共用头文件，用哈希清单证明测试
   没有被改弱，改动逐条写入去重报告（含未处理的残留项）。
7. **功能裁剪的判断**：早期做过 HTTP/MySQL 团队共享库与工艺批注（含幂等重试、修订冲突），
   个人项目里没有真实团队协作场景，服务端维护成本高、验证成本也高，最终按需求方要求整体移除，
   把精力收敛到单机查看这条主线上。这件事可以讲成**范围管理能力**，而不是“没做完”。

## 6. 未实现与已知限制（面试官问“还有什么没做”时照此回答）

- **制造级标注没有**：尺寸读数是全局外包络，不支持公差、基准、形位公差与工程图导出。
- **CAD 编辑没有**：只读查看，不支持布尔运算、参数化建模、IGES 与厂商原生格式
  （`.sldprt`、`.catpart` 等）。
- **只接受闭合实体**：开放面、壳、线或混合文件整份拒绝（宁可不给，也不给半个模型）。
- **展开/拉远只是显示效果**：不代表真实装配顺序、运动或碰撞约束，不做装配仿真。
- **多人协作已移除**：当前版本没有共享库、批注与权限体系；历史实现（含 Redis 缓存、
  修订冲突、幂等重试）保存在标签 `v1.1.1` 里，可作技术讨论材料。
- **性能与兼容性未量化**：未在其它电脑/其它 Qt 版本/无 Qt 环境做安装级验证；未做十万级三角
  以上装配的流畅度、长时间运行的内存与句柄量化；高 DPI 多显示器组合未覆盖。
- **真人验收未做**：仓库里的“模拟用户验收”“独立审查”是自动/代理结论，不等于真人满意度验收。

## 7. 现场演示脚本（约 6 分钟）

准备：交付目录完整（不要只复制 exe），保留 `samples\cad\` 里的 STEP 样例，提前确认
`cad-runtime` 存在（首次启动会慢一些）。

| 步骤 | 操作 | 讲解要点 |
| --- | --- | --- |
| 1 | 双击 `设备查看器.exe` | 自带 Qt 与 CAD 运行库，无需安装；程序图标已嵌进 exe |
| 2 | 左侧清单点选零件、搜索、隐藏/隔离/显示全部 | Controller 是唯一状态来源；隐藏不清选择，显示全部退出隔离 |
| 3 | 拖动旋转、右键平移、滚轮缩放、短点拾取 | 交互契约有原生断言；短点是拾取，双击空白只清选择、保留单件展示 |
| 4 | 依次切换彩色装配 / 工程轴测 / 二维正交 / 三视图 | 三视图同毫米比例、各栏独立视线；右下角方向轴是真实投影 |
| 5 | 打开尺寸边缘读数、改方向轴位置、展开、单件拉远 | 都是内存态显示效果；源参数只读，不会写回资料库 |
| 6 | 导入 `samples\cad\Yellow_gearmotor_straight.step` | 转换在受限子进程；等待期间可继续旋转，也能取消；取消后原设备不变 |
| 7 | 导入一个故意写错的 JSON | 报错定位到 `parts[i].字段`，原设备与资料保留 |
| 8 | 关掉程序重新打开 | 重启后源参数与导入时逐字段一致（持久化 + 只读回读） |
| 9 | 打开 `文档\` 里的验证记录与去重报告 | 自动检查、原生图形验收、资源基线、重构量化数据都是可复算的 |

现场容易翻车的地方：

- 只复制 exe 到别处运行 → 缺 `Qt6*.dll`、`platforms\qwindows.dll`、`sqldrivers\qsqlite.dll` 会起不来。
- 现场导入超大或非闭合 STEP → 会被整份拒绝，提前说明这是设计取舍，不是故障。
- 演示前删过 `data\` 目录也别慌：程序会自动重建内置样例设备。
- 如果机器的 OpenGL 上下文创建失败，程序会走软件回退并在渲染描述里如实标注——这时先讲两条
  路径的设计，再换机器演示原生路径。

## 8. 不要说的话

- 不说“零 Bug/零泄漏/支持所有 CAD 格式/多人协作平台”——事实是单机查看器，且有明确未实现清单。
- 不把自动检查、独立审查、模拟用户验收说成“真人验收通过”。
- 不把历史版本（1.1.1 的共享库、82 件装配验证）说成当前版本的能力；要讲就标明版本与出处。
- 不夸大性能：没有跨机器、超大型装配与长时间运行的量化数据。
